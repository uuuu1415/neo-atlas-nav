# 实施计划与验收

需求源：`PROJECT_SPEC.md`。真实进度：`STATUS.md`。本文件不以勾选替代验证记录。

## 阶段 0：仓库与恢复基础

- 同步指定仓库、保留原有提交，并按授权公开。
- 建立需求、执行规则、实施阶段与状态文件。
- 核实 Git 状态及仓库可见性；记录应用尚未开始实现。

## 阶段 1：项目基础与持久化

- 核实官方稳定工具及兼容要求，初始化 Next.js/React/TypeScript、shadcn/ui、样式和代码质量检查。
- 实现 SQLite 结构、迁移、共享 Zod 输入类型和 JSON 设置存取。
- 实现 settings 的 revision 冲突、原子替换、备份与格式迁移。
- 验收：类型/Lint/格式/构建；数据库重启读写；设置并发、损坏、写入失败和旧格式恢复。不可用清空数据通过测试。

## 阶段 2：导航、管理与导入导出

- 实现首页、管理、设置页面及真实数据接口，包含过滤、排序、批量操作、回收站。
- 实现书签解析、预览、去重统计与项目 JSON 备份恢复。
- 验收：核心操作和刷新/重启一致；导入重复、嵌套文件夹及错误条目；备份再恢复数据与顺序一致。

## 阶段 3：信息抓取与手动巡检

- Metascraper 真实元数据预览、图标候选和失败回退，保留手动字段与原 URL。
- 手动巡检任务、进度、取消、重试、真实状态记录；不加计划巡检。
- 验收：固定 HTML fixtures 覆盖完整/缺失元数据、相对 URL、重定向、非 HTML 与超时；实时网站仅作补充。
- 验收：403/429/超时不归为永久失效；没有自动改 URL、删除、AI 补全或虚构进度。

## 阶段 4：玻璃拟态与动效完善

- 视觉基础从阶段 1 建立并贯穿开发；本阶段集中完善一致性与性能，不到最后才替换全部 UI。
- 完成需求中的动效场景、共享参数、响应式和无模糊降级。
- 验收：深浅色正文与焦点清晰；鼠标/触控/键盘；快速连续切换；丰富/简洁/关闭与系统减少动态效果。
- 使用 1,000 条固定测试数据检查搜索、列表和动效，记录设备/浏览器及测量结果，必要时采用分页或窗口化，不能凭观感声称固定帧率。

## 阶段 5：原生安装与完整更新回退

- GitHub Actions、正式 Release 打包、Node 运行时与 SQLite 原生依赖、一键安装、systemd 单元。
- 实现独立更新服务和版本检查，数据库/JSON 迁移、健康检查、互斥与失败回退。
- 验收：实际目标 Linux 中首次安装、重复安装保留数据、开机启动、端口设置、版本更新与故障恢复。
- 发布包必须实际启动并完成 SQLite 读写；检查脚本和构建成功不能替代 Linux 测试。
- 缺少 Linux 环境或服务器信息时记录未验证项，继续可独立完成的工作，不编造部署。

## 每个阶段的交付要求

- 更新 STATUS：实际变更、执行过的检查、结果、遗留问题与下一步。
- 区分已实现未验证和已验证，记录当前操作以便中断恢复。
- 使用真实 Git 状态区分未提交、本地已提交和远程已推送。
- 只扩大测试到当前变更和未解决问题所需范围，不反复运行没有新信息的检查。
