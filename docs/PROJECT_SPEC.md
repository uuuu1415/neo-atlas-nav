## 已接受的实施方案

### 技术基础

React + Next.js App Router + TypeScript；Tailwind CSS + shadcn/ui；Drizzle ORM + better-sqlite3；Motion 与 dnd-kit；元数据提取使用 Metascraper。实施前重新核实正式版兼容性、类型定义与许可证，具体版本以验证后的锁文件为准。

### 页面与数据

- 首页：分类侧栏、搜索框、标签筛选、置顶、网站卡片；站内搜索名称、描述、URL，外部搜索入口明确区分。
- 管理：网站、单层分类和标签增删改；分类及分类内网站拖拽与按钮排序；批量分类、标签、置顶和删除。
- 网站字段：名称、URL、描述、分类、标签、置顶、排序位置、远程图标 URL，以及必要的时间和来源信息。
- 删除网站进入回收站，支持恢复和手动永久删除，不自动清空；删除分类时网站移入“未分类”。
- 浏览器书签 HTML 和项目 JSON 导入：预览、重复 URL 默认跳过、无效条目统计。嵌套文件夹按完整路径转换为单层分类。
- 项目 JSON 导出与完整恢复包含网站、分类、标签、顺序和设置。恢复前预览并备份现有内容。

### JSON 设置

- `settings.json` 与应用版本分离，位于持久化目录，包含 schemaVersion、revision。
- 字段分组：站点名称/描述/Logo URL；默认主题/主题色/卡片密度/描述显隐/动效等级；默认分类/链接打开方式/外部搜索引擎；抓取超时/缓存/默认填充行为；软件更新检查开关/周期（默认 24 小时）。
- Zod 结构统一校验，串行保存、临时文件原子替换、有效备份、并发编辑版本冲突检测。
- 损坏 JSON 保留原文件并提示，有有效备份时恢复并提示，不能静默清空。
- 后台修改立即生效；直接编辑磁盘文件后重启生效。支持设置导入、导出、恢复默认；设置格式变化有迁移。

### 信息获取与手动巡检

- 输入链接 → 点击获取 → 预览 → 手动调整 → 保存。仅提取真实网页 HTML 元数据，缺失留空。
- 图标候选解析相对 URL，无合适候选时尝试站点 favicon；仅存远程地址，可手动替换，显示失败使用占位图。
- 默认填充空字段，替换已有字段由用户选择。保留原 URL，重定向地址展示为候选；记录来源与抓取时间。失败仍可保存。
- 请求有超时、响应大小、重定向和并发上限，避免任务长期占用。
- 巡检只在点击后执行，支持单条、选中项、全部、进度、取消和重试，不递归发现网站。
- 报告真实 HTTP 状态、超时、网络错误和重定向。一次失败不等于永久失效；不自动修改网址或删除条目。
- 以部署服务器的网络可达性为依据，不能宣称服务器探测等于用户浏览器可达性。

### 玻璃拟态与动效

- 中文响应式界面，深浅色主题分别设计。
- 柔和渐变底色；侧栏、顶部工具栏、网站卡片、弹窗和浮动工具条广泛使用半透明、背景模糊、细边框、高光与阴影。
- 输入和正文保持清晰对比；避免多层模糊；无 backdrop-filter 支持时实色降级，不依赖持续动态背景。
- 动态覆盖分组入场、悬停/按压、选中指示器、筛选重排、侧栏/抽屉、拖拽抬起与归位、置顶、批量工具栏、删除恢复、弹窗、表单、抓取、巡检、更新、主题与保存反馈。
- 时长集中：微反馈约 120–180ms、普通 200–280ms、大型 300–420ms。首屏有限错峰，可中断，不阻塞输入或导航。
- 优先 transform/opacity；dnd-kit 和 Motion 不共同控制同一层 transform。
- 动效等级：丰富（默认）/简洁/关闭；系统减少动态效果优先。关闭动画仍保持功能与键盘反馈。
- 进度基于真实任务，不能虚构百分比；性能通过目标环境测量，不预先承诺帧率。

### GitHub 发布、安装与更新

- 正式版本 vX.Y.Z，GitHub Actions 检查测试并构建 Release 包。
- Next.js standalone 包包含匹配的 Node.js、SQLite 原生依赖和迁移程序，服务器不要求 Git/npm/现场编译。
- 一条安装命令；检查系统、架构、端口及 systemd，重复安装保留数据。程序、数据库、设置、任务状态和备份分开保存。
- GitHub 正式 Release 自动检查（默认 24 小时），支持手动检查；展示版本与说明，手动点击安装，不跟踪开发分支或预发布版。
- 独立 systemd 更新服务与网页进程分离。下载校验 → 暂停写入/停止应用 → 备份 SQLite 与设置 → 数据与 JSON 迁移 → 切换版本 → 启动与健康检查。
- 失败恢复对应程序、数据库、JSON；任务互斥、状态持久化，保留上一版本及备份。GitHub 不可用不影响当前服务。
- Dependabot 每周 PR 更新依赖，检查通过后发布，不直接升级服务器运行依赖。

## 默认条件和未验证项

- 用户只确认常见 Linux x86_64，未提供发行版。首批验收目标暂定 Debian 12、Ubuntu 22.04；未通过实测不得宣称支持。
- 默认端口 3000，可安装时配置。用户未提供部署主机、域名或 SSH 连接信息；不得编造部署结果。
- 用户“自己填写、不主动收录”没有明确限定公网或内网；保存链接不依赖巡检成功，以服务器可达性说明探测结果，不自动发现其他地址。
- 项目没有 AI 功能。优化提示词指开发助手的执行约束，已记录在根目录 AGENTS.md。
- 原先的“先本地运行”、Docker 建议、定时链接巡检与服务器缓存图标均被后续选择取代，不能在恢复后重新引入。
